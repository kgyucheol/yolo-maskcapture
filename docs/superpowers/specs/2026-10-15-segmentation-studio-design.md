# Segmentation Studio 설계

작성일: 2026-10-15  
상태: 사용자 `구현해줘` 승인 후 구현됨. 실제 송신기·학습·PT/ONNX 예측 검증은 실행 환경 의존성 설치 후 필요.

## 1. 목적과 완료 기준

사용자가 하나의 로컬 데스크톱 프로그램에서 ZMQ 영상 수신, 이미지 수집, 객체별 마스크 라벨링, 데이터셋 생성, 세그먼테이션 학습, PT/ONNX 추론 확인을 완료할 수 있게 한다.

- 기본 수신 주소는 `tcp://192.168.123.164:55555`다.
- 버튼으로 한 장 촬영하거나 사용자가 지정한 N초마다 자동 수집한다.
- 라벨링에서는 왼손으로 도구와 작업 상태를 제어하고 오른손은 마우스 조작에 사용할 수 있어야 한다.
- 학습과 추론 중에도 창 이동, 진행 상태 확인, 작업 중지가 가능해야 한다.
- 앱 재실행 후 프로젝트, 이미지, 클래스, 마스크와 마지막 작업 위치를 복원한다.
- 연결되지 않음, 모델 부재, 의존성 부재를 성공처럼 표시하지 않는다.

## 2. 현재 코드와 선택한 방향

현재 `zmq_source.py`와 `scripts/collect.py`, `scripts/train.py`, `scripts/infer_onnx.py`가 있다. UI와 라벨링 기능은 없으며, 기존 학습 기본 모델과 ONNX 후처리는 객체 검출용이다. 마스크 학습과 추론에는 세그먼테이션 경로가 필요하다.

PySide6 데스크톱 앱을 사용한다. 로컬 파일, 키보드 단축키, 캔버스 상호작용과 학습 프로세스를 직접 연결할 수 있기 때문이다. 브라우저 UI는 파일 접근과 서버 운용이 추가되므로 이번 범위에서는 선택하지 않는다.

기존 CLI 진입점은 유지하면서 공통 수집·데이터셋·학습·추론 서비스를 공유하도록 정리한다. 기존 검출 전용 ONNX 경로는 세그먼테이션 추론 경로와 명확하게 구분한다.

## 3. 화면과 시각 디자인

한국어 UI를 기본으로 한다. 색상은 짙은 남색 배경, 조금 밝은 패널, 청록색 주요 동작, 호박색 주의 상태를 사용한다. 클래스별 색상은 캔버스, 클래스 목록과 객체 목록에서 일치시킨다. 본문 대비와 선택 표시를 확보하고, 색상과 함께 텍스트 상태를 표시한다.

- 상단: 프로젝트명, 프로젝트 열기/만들기, 저장 상태.
- 왼쪽 탐색: 수집 → 라벨링 → 데이터셋 → 학습 → 추론. 각 화면에 이름과 상태를 표시한다.
- 중앙: 넓은 영상 또는 라벨링 캔버스. 도구 모음에 단축키 배지를 표시한다.
- 오른쪽: 선택한 화면의 설정, 클래스 및 객체 목록. 패널 폭을 조절할 수 있다.
- 하단: 연결 상태, 이미지 진행률, 작업 상태와 현재 화면 단축키 안내.

라벨링 화면은 이미지 목록, 캔버스, 클래스/객체 패널로 구성한다. 이미지 목록에서 미작업·작업 완료·명시적 배경 이미지를 구분한다. 현재 도구, 클래스, 미완성 마스크 상태가 캔버스 가까이에 표시된다. 툴팁과 단축키 도움말을 제공한다.

## 4. 왼손 중심 라벨링 조작

기본 키는 키보드 왼쪽에 모은다. 오른쪽 Enter/Delete/방향키 없이 핵심 작업을 끝낼 수 있어야 한다. 텍스트 입력, 숫자 입력, 파일 대화상자에서는 캔버스 단축키를 실행하지 않는다. 수집 화면과 라벨링 화면의 키는 화면별로 분리한다.

사용자는 먼저 클래스 이름을 태그로 등록한다. 오른쪽 패널에는 `1 컵`, `2 병`, `3 상자`처럼 번호와 이름을 함께 표시한다. 기본 순서는 `마스크 그리기 → F로 도형 완료 → 숫자 키로 태그 지정`이다. 숫자는 현재 선택 객체의 클래스를 지정하는 키이며, 단순히 다음 객체의 기본 클래스를 바꾸는 동작으로 처리하지 않는다. 기존 객체를 선택한 뒤 숫자를 눌러 태그를 변경할 수도 있다. 등록되지 않은 번호는 객체를 변경하지 않고 안내한다.

브러시는 마우스로 칠한 영역을 객체의 마스크에 추가하는 도구다. 지우개는 선택 객체의 마스크에서 칠한 영역을 제거한다. 둘 다 원본 이미지의 픽셀을 수정하지 않는다. 폴리곤은 점으로 경계를 정의하고, 브러시는 영역을 직접 칠하거나 경계를 보완하는 데 사용한다.

| 키 | 라벨링 동작 |
| --- | --- |
| Q | 객체 선택 및 꼭짓점 이동 |
| W | 폴리곤 마스크 그리기 |
| E | 사각형 마스크 그리기 |
| R | 브러시로 마스크 추가 |
| Shift+R | 지우개로 선택 마스크 수정 |
| F | 현재 마스크 도형 완료 후 선택 유지; 숫자로 클래스 지정 가능 |
| C | 미완성 마스크 취소 |
| X | 선택 객체 삭제; 실행 취소 가능 |
| Z / Shift+Z | 실행 취소 / 다시 실행 |
| A / D | 이전 / 다음 이미지 |
| S | 저장 |
| V | 마스크 오버레이 표시 전환 |
| Tab / Shift+Tab | 다음 / 이전 클래스; 캔버스에 포커스가 있을 때 |
| 1–9 | 선택 객체에 해당 번호의 클래스 태그 지정 |
| Space 누른 채 드래그 | 캔버스 이동 |
| 마우스 휠 | 커서 위치를 기준으로 확대·축소 |
| Ctrl+마우스 휠 | 브러시·지우개 크기 조절 |

Ctrl+S, Ctrl+Z, Ctrl+Shift+Z, Esc도 보조 키로 지원한다. Esc는 미완성 마스크를 취소한다. 클래스가 아홉 개보다 많으면 클래스 목록 클릭으로 선택 객체에 태그를 지정할 수 있다. Tab으로 클래스를 탐색한 뒤에도 선택 객체에 지정할 수 있으며, 패널 입력에 포커스가 있으면 Tab은 일반 포커스 이동으로 동작한다. 화면의 태그 번호는 1부터 표시하고, 데이터셋의 클래스 ID는 0부터 저장한다. 이 매핑은 프로젝트에 보존한다.

이미지 이동 전에 라벨을 자동 저장한다. 미완성 마스크 도형이 있으면 이동을 보류하고 `F 도형 완료 / C 취소` 안내를 표시하여 작업을 잃지 않게 한다. 도형 완료 후 클래스가 지정되지 않은 객체는 중립색과 `태그 미지정` 배지로 표시하고 임시 주석으로 보존한다. 그런 객체가 있는 이미지는 작업 완료로 처리하지 않으며 학습 데이터셋에서 제외하고 원인을 표시한다. 마스크 확정·삭제·꼭짓점 수정·브러시 작업·태그 변경은 객체 단위 실행 취소 이력에 포함한다.

수집 화면에서는 Space로 한 장 촬영하고 Ctrl+Space로 자동 촬영을 시작·중지한다. 버튼에도 같은 동작과 단축키를 표시한다.

## 5. 수집과 ZMQ

주소, 포트, SUB/PULL/REQ 방식과 connect/bind 설정을 UI에서 선택한다. 기본값은 요청 주소, SUB, connect다. 기존 수신 코드와 같이 단일 메시지 또는 multipart 마지막 프레임의 JPEG/PNG 바이트를 가정한다. pickle/raw 배열 등 다른 송신 포맷은 이 설계의 자동 해석 대상이 아니다. 잘못된 데이터는 UI에서 디코딩 오류로 표시한다.

소켓은 수신 작업 스레드 안에서 생성·사용·종료한다. 짧은 polling과 중지 신호로 종료를 처리한다. multipart 수신에서는 마지막 파트만 남을 수 있는 무분별한 CONFLATE 사용을 피하고, UI로 전달하는 최신 이미지 슬롯을 제한해 지연과 메모리 증가를 막는다. REQ 타임아웃 후 재생성 시 사용자 timeout과 bind/connect 설정을 유지한다.

수동 촬영은 수신된 유효 프레임이 있어야 가능하다. 자동 촬영에는 양수 간격을 요구하고 monotonic clock을 사용한다. 연결이 끊긴 동안에는 이전 프레임을 반복 저장하지 않는다. 유효 프레임이 다시 도착하면 촬영을 재개한다. 파일명은 충돌하지 않게 생성하고 저장 성공 후에만 장수를 증가시킨다. 프레임 수신 시각, 파일명, 출처를 메타데이터에 기록한다.

## 6. 프로젝트와 마스크 데이터

프로젝트 디렉터리는 다음 데이터를 가진다.

```text
project.json             # 클래스, 연결 설정, 마지막 작업 위치, 버전
images/                  # 수집 또는 가져온 원본 이미지
annotations/             # 이미지별 객체·작업 완료 상태·메타데이터
masks/                   # 브러시 편집을 포함한 객체별 이진 PNG 마스크
datasets/<생성 ID>/      # 생성 시점이 고정된 학습·검증 데이터셋
runs/<실행 ID>/          # 학습 로그, 가중치와 내보낸 ONNX
predictions/             # 사용자가 저장한 추론 시각화와 결과
```

객체는 고유 ID, 클래스 ID, 폴리곤과 이진 마스크를 갖는다. 태그 미지정 임시 객체의 클래스 ID는 null로 보존한다. 원본 이미지 좌표를 기준으로 저장하며 확대·축소 상태와 무관하다. 브러시는 이진 마스크를 편집하고, 폴리곤은 표시·데이터셋 생성 시 일관된 방식으로 변환한다. 프로젝트 JSON과 주석은 임시 파일 후 교체 방식으로 저장한다. 저장 실패 시 미저장 상태를 유지한다.

미작업 이미지와 의도적으로 객체가 없는 배경 이미지를 구분한다. 클래스 ID는 안정적으로 유지하며 클래스 이름 변경은 기존 객체 참조를 유지한다. 사용 중인 클래스의 삭제는 해당 객체를 재지정하거나 제거하기 전까지 막는다. 이미지 가져오기는 원본을 복사하고 파일명 충돌과 동일 stem의 라벨 충돌을 방지한다.

## 7. 데이터셋 생성

완료된 라벨과 명시적으로 확인한 배경 이미지만 포함한다. 클래스 범위, 마스크 크기, 비어 있는 객체, 잘못된 좌표와 너무 작은 윤곽을 검사하고 이미지별 오류를 보여 준다. 최소 두 이미지와 비어 있지 않은 train/val 분할을 요구한다. 검증 비율과 고정 seed를 입력받아 재현 가능한 분할을 만든다.

YOLO segmentation 라벨은 `class x1 y1 x2 y2 ...` 정규화 좌표로 저장한다. 브러시 마스크의 분리된 영역은 연결 성분별 인스턴스로 내보내고 생성 보고서에 수를 표시한다. 폴리곤 형식으로 표현할 수 없는 내부 구멍은 학습용 내보내기에서 채워지며, 원본 이진 마스크는 보존한다. 변환 대상과 건수를 생성 보고서에 명시한다.

새 출력 디렉터리에서 생성하고 검증을 통과한 뒤 완료 상태로 전환한다. 기존 데이터셋과 원본 데이터를 덮어쓰거나 삭제하지 않는다. `data.yaml`, 분할 목록, 클래스, seed, 통계와 변환 경고를 함께 저장한다.

## 8. 학습과 ONNX 내보내기

사용자가 지정한 `yolo11s-seg.pt`를 기본 모델로 사용한다. 원본 848×480을 보존하고 학습 imgsz는 기본 864로 설정하며 rect 옵션을 제공한다. 사용자가 초기 모델 파일/모델명, epoch, 이미지 크기, batch, CPU/GPU를 선택한다. 검출용 모델을 잘못 선택하면 학습 시작 전에 이유를 표시한다.

학습은 별도 프로세스로 실행하여 UI를 막지 않는다. 실행별 디렉터리와 설정을 보존한다. UI는 로그, 진행 epoch, 가능한 학습 지표와 결과 경로를 표시한다. 중지 요청은 해당 작업 프로세스에만 전달하고 실제 종료가 확인된 후 상태를 바꾼다. 실패와 사용자 중지를 완료와 구분한다.

성공한 학습의 best.pt를 UI에서 선택할 수 있다. ONNX 내보내기는 별도 동작으로 제공하고 진행·성공·실패와 실제 생성 파일 경로를 표시한다. 학습·내보내기에 필요한 의존성이나 사전 학습 파일이 없으면 설치/파일 준비 방법을 안내한다. 실제 모델·의존성 다운로드는 네트워크가 가능한 환경에서 필요하다.

## 9. PT/ONNX 추론

지원 범위는 Ultralytics로 학습·내보낸 세그먼테이션 PT/ONNX 모델이다. 임의의 ONNX 입출력을 모두 지원한다고 표시하지 않는다. 공통 추론 인터페이스로 모델 로딩과 이미지별 예측을 감싸고, ONNX 실행에는 ONNX Runtime을 사용한다. 지원하지 않는 task/모델 형식은 명확히 거절한다.

저장 이미지·이미지 폴더·현재 ZMQ 스트림을 입력으로 선택한다. 클래스명, 신뢰도, 객체별 마스크와 경계, 처리 시간 및 FPS를 표시한다. 신뢰도/IoU 임계값을 변경할 수 있으며 결과 이미지 저장을 제공한다. 데이터 수집과 실시간 추론은 하나의 수신 프레임을 공유한다.

모델 로드와 추론은 UI 밖에서 수행하고 대기열을 제한한다. 중지 또는 모델 변경 후 이전 작업 결과가 화면을 덮어쓰지 않게 작업 ID를 사용한다. PT/ONNX 비교 검증은 동일 이미지에서 마스크 위치, 클래스와 신뢰도에 대해 수행하며 수치가 완전히 같다고 가정하지 않는다.

## 10. 구현 경계와 검증

UI, 프로젝트 저장, 주석/마스크 편집, ZMQ 수집, 데이터셋 생성, 학습 프로세스, 추론 어댑터를 분리한다. 무거운 학습 의존성을 UI 시작과 동시에 불러오지 않아, 모델 설치 전에도 프로젝트 관리와 라벨링을 사용할 수 있게 한다.

자동 검증은 다음 위험을 다룬다: 주석 저장/복원, 실행 취소, 마스크 좌표 변환, 데이터셋 검증과 재현성, 원본 보존, ZMQ multipart/timeout/종료, 중지 후 결과 무시. GUI는 가능하면 offscreen으로 시작해 도구 선택과 입력 포커스에 따른 단축키 차단을 확인한다.

실기 검증은 실제 송신기의 프레임 수신, N초 촬영과 수동 촬영, 왼손 조작만으로 이미지 하나를 라벨링하고 다시 열기, 작은 데이터셋으로 짧은 학습, PT와 내보낸 ONNX의 동일 이미지 추론을 포함한다. 네트워크·GPU·의존성 제약으로 수행하지 못한 검증은 수행한 검증과 구분해서 기록한다.

현재 가상환경은 Python 3.10이고 주요 ML/ZMQ 패키지가 설치되어 있지 않다. 기존 설치 로그에는 DNS 해석 실패가 있다. 현재 디렉터리에서 git 저장소도 인식되지 않으므로 이 문서의 git commit은 할 수 없다. 이는 문서 작성과 이후 구현 파일 작성 자체를 막지는 않는다.

이번 범위에는 SAM 등 대형 모델을 이용한 자동 마스크 생성, 다중 사용자 협업, 클라우드 학습, 배포용 설치 프로그램은 포함하지 않는다. 폴리곤·사각형·브러시·지우개를 통한 수동 마스크 작업을 완결하는 데 집중한다.
